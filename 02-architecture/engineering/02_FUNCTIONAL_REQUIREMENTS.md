## B. Кассир (STORE) — MUST

| ID | Требование |
|----|------------|
| FR-S01 | Вход только если Telegram ID привязан к активному Store |
| FR-S02 | Поиск клиента по телефону |
| FR-S03 | Просмотр баланса клиента |
| FR-S04 | Начисление: телефон → сумма покупки → авторасчёт баллов → PENDING |
| FR-S05 | Кассир **не** вводит количество начисляемых баллов |
| FR-S06 | Списание: телефон → сумма покупки → авторасчёт max / FIFO → preview → подтверждение |
| FR-S07 | Кассир **не** вводит количество списываемых баллов |
| FR-S08 | Операция сохраняет store_id, название/адрес магазина, telegram_id оператора |
| FR-S09 | Нет доступа к настройкам, полной статистике, админам |

## D. Бонусная логика — MUST

| ID | Требование |
|----|------------|
| FR-B01 | 1 балл = 1 ₽ |
| FR-B02 | Накопительные и подарочные раздельно |
| FR-B03 | Начисление = **отбросить копейки** (floor) от суммы × процент / 100; если сумма < мин. порога — баллы не начисляются |
| FR-B04 | Списание = минимум из (доступный баланс; **отбросить копейки** от суммы × max % / 100); кассир количество не вводит |
| FR-B05 | FIFO по expires_at ASC, accrued_at ASC, id ASC; тип баллов не влияет. Override порядка в настройках в v1 **нет** |
| FR-B06 | Автосгорание просроченных партий + операция **BONUS_EXPIRATION** |
| FR-B07 | ДР: авто gift + сообщение по шаблону |
| FR-B08 | Баллы за регистрацию (gift) по настройке |
| FR-B09 | Идемпотентность / защита от двойного клика |
| FR-B10 | Баланс не правится без операции в истории |
